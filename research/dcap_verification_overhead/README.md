# DCAP Verification Overhead Microbenchmark

Isolated measurement of the SGX-enclave cost on **DCAP quote verification** —
the only security-critical cryptographic operation the subscriber performs
on every attestation epoch.

Runs **N consecutive verifications** (default 1000) of a pre-captured TDX
quote against pre-cached DCAP collateral, with no network and no CVM in
the critical path. The same `benchmark.py` runs in two environments and
the delta is reported as the enclave overhead:

  - **Non-SGX (Python)** — plain Python on bare metal.
  - **SGX (Gramine)** — same code inside an SGX enclave via Gramine.

Two verifier implementations are measured side by side:

  | Verifier | What it checks | Matches |
  |---------:|:---------------|:--------|
  | `simple` | ECDSA-P256 signature + nonce binding | existing `t_quote_verify_ms` in the incremental-attestation paper figures |
  | `full`   | ECDSA + PCK cert chain + CRL + TCB evaluation + nonce | real DCAP pipeline (the verification a production subscriber should do) |

Both verifier paths call the project's existing code in
`research/sgx-tdx-attestation/common/protocol.py` and
`research/tdx-dcap-attestation/dcap_verifier.py`, so the numbers are
directly comparable to the rest of the paper.

## Prerequisites

On the **subscriber host**:

  - Python 3.10+ with `cryptography`, `requests` packages installed.
  - For the SGX run: Gramine 1.9+, SGX PSW, `libsgx-dcap-ql`, and
    `/dev/sgx_enclave` accessible.
  - For `prepare_inputs.py`: reachable PCCS (or direct internet access
    to `https://api.trustedservices.intel.com`). The default
    `collateral_fetcher.py` uses Intel's PCS; if you prefer a local
    PCCS, configure the PCCS URL in `research/tdx-dcap-attestation/`
    before running preparation.

On the **CVM**: the existing attestation agent reachable over mTLS,
exactly as used elsewhere in this repo. Alternatively you can reuse a
pre-saved TDX quote file instead of fetching one live (see below).

## Running the benchmark

### Step 1 — Prepare inputs (once)

Populates `inputs/` with one real TDX quote and the matching DCAP
collateral. After this step the benchmark is self-contained and
requires no network.

```bash
cd research/dcap_verification_overhead

# Option A: fetch a live quote from the CVM
make prepare TDX_HOST=<CVM_IP>                   # with mTLS disabled
# or
python3 prepare_inputs.py \
    --tdx-host <CVM_IP> --ca-cert ../sgx-tdx-attestation/certs/ca.crt

# Option B: reuse an already-captured quote on disk
python3 prepare_inputs.py --quote-file /path/to/some_quote.bin
```

Expected output: `inputs/sample_quote.bin`, `inputs/sample_nonce.txt`,
`inputs/collateral.pkl`, `inputs/metadata.json`.

### Step 2a — Non-SGX run

```bash
make run-python                 # 1000 iters per verifier
# or tune:
make run-python ITERS=2000 WARMUP=100
```

Writes `results_python.csv` and `results_python_summary.json`.

### Step 2b — SGX run (Gramine)

Build the enclave once:

```bash
make all                        # generates verifier.manifest.sgx + verifier.sig
```

Run the benchmark inside the enclave:

```bash
make run-sgx                    # writes results_sgx.csv
```

If the enclave refuses to write to `results_sgx.csv`, make sure the file
exists (the Makefile `touch`es it, but `sudo` permissions can break
this) and is listed under `sgx.allowed_files` in
`verifier.manifest.template`. The benchmark script falls back to
`/tmp/results_sgx.csv` if the target is read-only.

**Important:** run steps 2a and 2b on the **same physical host** to
avoid cross-machine variance confounding the measurement. This is the
whole point of the microbenchmark.

### Step 3 — Generate comparison figures

```bash
make plot
```

Writes to `charts/`:
  - `fig_verify_boxplot.pdf`        Distribution comparison
  - `fig_verify_cdf.pdf`            CDF of per-iteration latency
  - `fig_verify_slowdown.pdf`       min/p50/mean/p95/p99 slowdown bars
  - `fig_verify_histogram.pdf`      Overlapping histograms

Also writes `summary.json` with per-verifier statistics and slowdown
ratios.

## Interpreting the results

- **Post-warm-up overhead** lives in the p50 / mean. Gramine-SGX
  Python adds ECALL/OCALL transition cost on every library call and
  paging cost if the working set exceeds EPC. Typical published
  numbers: 1.1× – 2× on pure-CPU crypto workloads.
- **Tail (p99, max)** reveals EPC page eviction and TLB-shootdown
  events. These are legitimate SGX behaviors and should be reported
  honestly as the worst-case cost of cryptographic isolation.
- **The first iteration** in the `sgx` run is the one most affected
  by cold caches (Intel DCAP library collateral, PCK cert parsing,
  etc.). The 50-iter warmup discards this so your reported mean/p50
  reflects post-warm-up execution. If you *want* to also report the cold-start
  number, check the first line of `results_sgx.csv` after the warmup
  (or re-run with `--warmup 0`).
- **Enclave bring-up time** is NOT measured here — it is a one-time
  cost paid once per subscriber lifetime. Measure it separately by
  timing `gramine-sgx ./verifier /bench/benchmark.py --iters 0` from
  outside.

### How to cite the numbers in the CCS paper

After running, `summary.json` gives you mean/p50/p95/p99 for each
verifier in each mode and the slowdown ratios. Sample phrasing:

> *DCAP quote verification incurs a Gramine-SGX overhead of
> **X.Xx (mean) / Y.Yx (p99)** relative to native Python on the same
> host, measured across 1000 consecutive verifications of a
> pre-captured TDX quote with pre-cached collateral. In absolute
> terms this is Z.Z μs per attestation, consistent with published
> measurements of Gramine's ECALL/OCALL transition cost.*

## Troubleshooting

- **`prepare_inputs.py` fails parsing FMSPC**: the quote's PCK cert
  chain may be absent. Fall back to specifying the FMSPC directly by
  editing the script, or use a live CVM that embeds the PCK chain.
- **`make all` fails with "trusted file not found"**: inspect
  `verifier.manifest.template`'s `sgx.trusted_files`. Typically the
  Python version or arch_libdir auto-detection is off for your
  distro.
- **Enclave OOMs**: raise `sgx.enclave_size` in the manifest template
  (default 2 GiB). The cryptography library's CFFI backend plus
  Python itself can push past 1 GiB resident.
- **`/dev/attestation` not detected in SGX mode**: Gramine didn't
  start in SGX mode — check `gramine-sgx` vs `gramine-direct` and
  the `/dev/sgx_enclave` device permissions.
